How weekly updates work

Data source

Each of the 10 stalls keeps one tab in a shared weekly menu spreadsheet, using the same fixed columns below. One menu runs the whole week — there's no per-day variation to fill in. A vendor only ever edits their own tab, so there's no risk of one stall overwriting another's menu.

Weekly cadence

Stalls fill in next week's tab by Friday afternoon, and that same menu runs Monday through Friday — it doesn't change day to day. The board always reads whichever week is marked current, so there's no manual copy-paste between systems.

New-dish detection

A dish is flagged NEW the first time its name appears against a stall — after that week it quietly folds into the regular menu shown under This Week's Menu. Vendors can also override the flag by hand for relaunches.

Filtering

The dietary, allergen, and budget preferences a student picks at the start run entirely in the browser against the current week's data, so results update instantly with no server round-trip once the page has loaded.

Getting this onto WeCom

This page is a self-contained front end, already laid out for a phone screen. To put it in front of students, IT needs: somewhere internal to host it, a small weekly step that turns the consolidated spreadsheet into the data file this page reads, and a link to it from a WeCom custom menu or Workbench app so it opens full-screen in WeCom's built-in browser. No WeCom mini-program build is required for this version.
